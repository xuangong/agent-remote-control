# O11: The Controller's session-core modules read shared state through a typed context

- Found in: M10
- Owner step: later
- Status: closed

## Item

The Controller's session-core modules read shared state through a typed context, which renames the coupling rather than removing it. The bindings, the idle sessions and the operation cache need one owner module each

## Status

closed (O11 slice, 2026-11-19): the session core no longer shares mutable state through its context. `ProviderRegistry` owns the registrations and catalogs, `AttachmentLedger` the prepared sessions, native attachments, worker-tool records and idle uncertainty, and `BoundSessions` the bindings and families; each is the only place its state is assigned, `host.ts` builds them and the modules receive their interfaces. The operation cache (`OperationCache`, session runtime) and the idle sessions (`createIdleSessions`) already had one owner and are passed as interfaces, idle narrowed to the five operations the core uses. `SessionCoreContext` 50 to 44 members, raw shared collections on it 6 to 0; `host.ts` 573 to 551 lines. 25 unit tests (registry 8, ledger 8, bound sessions 9), 39 of 39 mutations caught; no old test deleted (the rules were inline in `host.ts` with no test of their own)
