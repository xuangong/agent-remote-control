# GitHub Copilot provider

This package adapts the official `@github/copilot-sdk` 1.0.11 to the standalone Provider SDK. It owns an official Copilot CLI process over SDK stdio, with normal installed dependencies and no Borgee service or private runtime transport dependency.

The default executable is the public `copilot` bin declared by the pinned `@github/copilot` 1.0.83 package. It is resolved through Node package resolution because SDK 1.0.11's default optional platform-package lookup does not resolve under this workspace's pnpm dependency layout. `executable` explicitly overrides this path. Authentication uses the native CLI environment; this package does not persist tokens.

## Supported behavior

- Create, native discovery, disconnect/resume, durable history followed by one history boundary, deduplicated live events, append-only text deltas with final suffix reconciliation, incremental reasoning, bounded tool output snapshots and structured results, context usage, and compaction. Completed durable permission pairs become historical interaction records; background follow-up turns retain their identities on resume.
- Immediate or queued root input, steering and main-turn interrupt. One public turn spans model steps and steering with the same native interaction ID; a queued new interaction closes the prior public turn even when only one final `assistant.idle` is emitted; assistant idle does not disconnect the native session or terminate background tasks. Child completion follows native task idle snapshots, including repeated follow-up rounds and snapshots received during history loading.
- Permission events expose one-time allow/deny and native-supported session grants through the public pending-permission RPC. Human intent and structured command/path details replace raw JSON summaries. Path access and read-tool approval are distinct native checks and are labeled separately. Session command/write grants require the native eligibility flag; managed mandatory approvals never offer session grants. Questions preserve native choices and freeform constraints. Native request IDs, event agent identities, and native tool-call ownership own prompt retirement and main-versus-child cancellation; callback session IDs are never interpreted as child identities. Responses are validated against the actual pending request.
- Native session model choices and native user-invocable enabled skills. Skill invocation resolves its canonical slash command through public `commands.invoke` and sends the returned agent prompt with its native display text. Documentation revalidates the current native directory, reads only regular files without following a final symlink, and rejects bodies larger than 256 KiB. Markdown bytes use the existing `text/plain` resource media type.
- Parent-owned child task directory, filtered paginated child event-log history, live child routing, repeated task input and task cancellation. Disposing a child view does not cancel the task or disconnect the parent. Children are never resumed as independent root sessions.

## Question callback limitation

SDK 1.0.11 requires `onUserInputRequest` to enable `ask_user`, but its callback omits native request and agent IDs. The adapter pairs a callback only when exactly one unbound `user_input.requested` event has the same complete question/choice/freeform payload. Different questions may run concurrently. Concurrent identical unbound questions fail explicitly with a visible error and terminal prompt receipts; the adapter never guesses FIFO ownership or invents an answer. Native completion events retire matching prompts, including responses or cancellations from another native client.

## Experimental native interfaces

`session.rpc.model`, `skills`, `commands`, `tasks`, `interruptMainTurn`, and `eventLog` are public **experimental** SDK APIs. Model and command controls are advertised only when their native directory calls succeed. Unavailable child event-log history fails explicitly; there is no filesystem or private RPC fallback. Copilot CLI 1.0.39 lacks `session.eventLog.read`; use the pinned runtime for full child views.

Workspace skill directories come from public native `client.rpc.skills.getDiscoveryPaths`; the returned canonical directories are supplied to session creation/resume. The adapter lists only enabled user-invocable skills the session actually loads; it does not scan hardcoded paths or infer global commands. Native model catalog availability depends on authentication. Model changes require idle state; a native deferred write is explicitly unconfirmed until a model-change event refreshes actual state. Runtime reasoning effort choices come from the selected native model and use authoritative readback. Planning uses native mode get/set; typed review maps exit-only, interactive continuation, and rejection, without substituting autopilot actions. Full filesystem/network bypass, independent child settings, arbitrary file reads, and child-view interaction ownership are not advertised. The tool-approval setting is described below.

`CopilotAgentProviderOptions` accepts `executable`, `env`, `requestTimeoutMs`, and `onDiagnostic`. `nativeSessionConfig.provider`, `nativeSessionConfig.skillDirectories`, `nativeSessionConfig.mcpServers`, and `useLoggedInUser` support explicit official SDK BYOK configuration and isolated local transport verification. Provider credentials are never copied into persistence handles. Dispose the provider to stop its owned runtime process.

## Normalized expression

- Native file-edit results preserve detailed output. `apply_patch` freeform input identifies file intent; completed unified diffs use the existing `file_changes` result format with added/modified/deleted/renamed metadata. Failed calls never turn their proposed patch into a completed diff. Unknown formats remain bounded raw text. See the [complete event inventory](../../docs/current/agent-remote/copilot-normalized-events.md) for every normalized variant and remaining gaps.
- Native `session.todos_changed` refreshes the session SQL todos through a serialized reader. Current todos are also loaded on open; unchanged snapshots are suppressed and an emptied list is published.
- Native usage exposes input/output/cache-read tokens and context used/capacity. Copilot billing multipliers and AI credits are not USD and are not mapped to `totalCostUsd`.
- Plan callbacks and MCP elicitation retain identity-bearing native requests. Only uniquely matching callbacks bind. Flat supported forms validate constraints and redact explicitly sensitive answers; unsupported schemas are canceled, not flattened. HTTP(S) URL elicitation uses existing external-action responses. SDK elicitation invokes the callback before broadcasting the request; binding waits for that synchronous broadcast.
- Root image input uses native blob attachments. Native model image limits narrow the adapter limits when supplied; unknown BYOK catalogs keep the adapter transport limits. Native messages expose image parts and session-owned resource references. Durable `session.binary_asset` bytes reconstruct input images on resume; missing bytes stay unavailable. Images are bounded to 10 MiB each, 20 MiB per submitted message, 8 images per submission, and 64 MiB retained per session, further narrowed by native model metadata. Native prompt text and attachments use the SDK's grouping semantics.
- The Permissions control uses the confirmed native `setApproveAll` tool toggle. It does not disable independent path/URL or managed rules. Fresh sessions initialize to asking; resumed sessions show an unknown policy until explicitly set because this stdio runtime has no policy getter. SDK-declared `getAllowAll/setAllowAll` are not implemented by the tested runtime and are not exposed. The shared UI changes settings while idle; individual pending prompts can offer session grants.
- History never recreates process-local pending callbacks. Questions, plans, forms and reasoning absent from the native durable journal cannot be recovered by inference; live JSONL recordings retain the normalized events that were actually observed. Parent-owned child approvals remain on the parent timeline after resume.

## Verification

Run `pnpm test:copilot` from the repository root. Behavior tests have 10-second per-test deadlines; real SDK/CLI loopback tests have 45-second deadlines and the root runner enforces a 540-second outer process deadline. Tests isolate `COPILOT_HOME`, remove token overrides, use a free loopback port and clean their owned processes/files.

The maintained native suite verifies queued versus steering interactions in live/resumed history, create/list/resume, actual skill body/argument expansion, question plus approval across model steps, root cancellation preserving successful child bash execution, repeated child input and child history reopening. Native root/child observations pass through the actual Relay TimelineStore/projector with exact-once text and preserved tool results; skill documentation passes through the actual ResourceIngestor. Additional native cases cover plan rejection, sensitive MCP form roundtrips, image input and restored image resources, persisted approval records, and SQL todo notifications. Unit tests cover callback ambiguity, cancellation/invalidation, live/history turn identity, incremental reasoning/tool output, model metadata, failed compaction and resource bounds. Manual authenticated ARDB checks are separate evidence; full native-product parity remains unverified. See the [support audit](../../docs/current/agent-remote/copilot-support-audit.md).

## Controller and native CLI handoff

`agent-remote-controller copilot resume <session-id>` coordinates the configured profile with the Controller. If another managed client owns it, choose **Interrupt and take over**, or pass `--take-over` for scripted use. Web takeover is in the read-only Chatbox. There is no safe-wait mode: current native work is interrupted, release is verified, and the same session ID resumes. Web-to-web takeover only transfers interaction authority and does not interrupt native work.

The Controller records requested handoff, forced exit, unexpected exit, and unconfirmed release separately. It never deletes native locks or replays interrupted input. Directly launched native clients and native selection menus do not register a managed handoff endpoint; close those clients yourself. An incomplete response or queued execution is not guaranteed to survive interruption. Native Windows takeover is not yet verified on a Windows machine.
