# E2E convergence: where each legacy Playwright spec went (2026-11-21)

Scope: every test of the two legacy Playwright tiers at `4c301368` (`design/im-session-service`):

- `pnpm test:e2e`: `packages/agent-e2e/specs`, 38 files, 183 tests on `chromium-desktop` (350 runs over six projects), against the recorded Relay and the Workbench's Vite server;
- `pnpm test:e2e:lab`: `packages/agent-remote-lab/e2e/*.spec.ts`, 14 files, 94 tests on `chromium-desktop` (278 runs).

Section 13 of [the target architecture](2026-11-18-target-architecture-and-tests.md) recorded both as failing on the Orchard page. The goal of the restructuring is that e2e covers the main flows (`packages/agent-e2e/flows`, section 5.6) and the cases that local runs found. Every test was put in one of four categories, passing tests too:

- **(a) duplicate**: deleted after the mutation check showed that every mutation it catches is also caught by a flow, a component test or a lower tier;
- **(b) main flow or local finding** that no flow covered: moved into `agent-e2e/flows` on the Orchard page;
- **(c) single-component behaviour**: moved to the component tier (`agent-remote-lab/e2e/components`, fixture pages on builder states) or to a unit test;
- **(d) device-specific** (a phone, WebKit, touch, the software keyboard): kept as a component project at 390x844 and in WebKit, or as a phone flow.

Both legacy tiers are empty and their commands are removed; the flows are the one e2e tier.

The flows went from 43 to 55 tests: E1 a new session in a folder made from Browse; E2 a message typed while offline, and a multi-line message (its own file); E3 a session the Host no longer has; E5 a handoff to another provider; E6 a fold seen on a second page, and E6b a group on two computers; E7 two pages converging on one Window; E12 signing in (5). Where an owner missed a mutation that the old test caught, the missing unit, App or component test was written first; each row says so. Findings that need a product decision are open items O54 to O58 of the target architecture.

## Method

The mutation check of [write-tests](../../../.agents/skills/write-tests/SKILL.md), section 5. For each rule a test asserts: one-line mutations of the source that implements it, one at a time, each restored after its run. Every mutation ran against the owner tests; a legacy test that passed at `4c301368` ran under the same mutation, and was deleted only if every mutation it caught was also caught by an owner. A legacy test that failed at `4c301368` (stale Orchard selectors or words) caught nothing as written: its rule was named from what it was written to prove, and an owner had to catch that rule's mutations. Where no owner did, the missing test was written first (category c or d).

Baseline at `4c301368`, `chromium-desktop`, one worker, no retries:

| Tier | Passed | Failed or timed out | Skipped | Time |
|---|---:|---:|---:|---:|
| `agent-e2e/specs` | 82 | 53 | 48 | 12.8 min |
| Workbench specs | 53 | 36 | 5 | 11.9 min |

The mutation runs used copies of the worktree (APFS clones, one per area), so a mutation never reached the branch.

## The native browser specs

Three files drive the page against a real CLI runtime and are skipped unless the runtime is selected: `codex.spec.ts` (6 tests, `BORGEE_CODEX_TEST_EXECUTABLE`, the Codex app-server against its local model-response fixture), `dsh-delivery.spec.ts` (1, `AGENT_REMOTE_DSH_DELIVERY_FIXTURE=1` with `DSH_REPO`) and `live-dsh.spec.ts` (2, `DSH_REPO`). They are native-tier tests, not e2e: they moved to `packages/agent-e2e/native` with `playwright.native.config.ts`, which keeps only the codex and dsh Relay modes of the old config, and run with `pnpm test:native:browser`, by hand or nightly (the runbooks `docs/runbooks/codex-debug.md` and `dsh-debug.md` name it). Without a runtime the command skips all nine in about 2 s. They were not run here: no runtime was selected, and the task needs no real CLI. Their selectors predate the Orchard page (`connection-summary`, `.lab-shell`); the next run with a runtime re-points them.
