# O22: On the e2e stack the page's 'Take control' did not return control from a terminal

- Found in: M14
- Owner step: M15
- Status: closed

## Item

On the e2e stack the page's 'Take control' did not return control from a terminal

## Status

closed: a stack artifact, not a product defect. The scripted provider named the terminal owner `terminal-1`; `sessionAttachFailure` forwards a native owner only when its generation is a UUID (every owner record of the Controller is one, and the take-over request accepts no other shape), so the Relay learned no owner, the page offered a plain 'Take control', and the Relay's lease grant was followed by a refusal from the Controller. `terminalTakes` now uses a UUID; the page then offers 'Interrupt and take control', and E4 clicks it, sees the composer return and a send reach the provider. The rule that a non-UUID owner is dropped is pinned in `session-errors.test.ts`
