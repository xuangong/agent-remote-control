# Provider gaps and implementation paths

Read the [current support matrix](provider-support.md) first. This document explains why selected DSH and Claude cells are partial or unavailable, what Paseo actually implements, and what would justify changing those cells. Feasibility is not delivered support: the matrix remains authoritative until implementation and acceptance evidence exist.

## Evidence baseline

Source comparison on **2026-09-11**: Agent Remote runtime `614d9fe` and support inventory `7349294`; Paseo `463415ae846cbcfef0df691e413a1a73a9213757`; DSH `a66e4702047846cdaa10c66c9d3df3951f5ea70d`. Paseo declares Claude Agent SDK **0.3.246**; Agent Remote pins **0.3.247** and Claude Code **2.1.247**. The SDK declarations cited below are from the installed `@anthropic-ai/claude-agent-sdk/sdk.d.ts` at that pinned version, not a claim about all SDK releases.

Paseo and DSH references are immutable source links. Reading their implementations or SDK declarations establishes an implementation candidate, not that the behavior has passed Agent Remote's native or transport tests. The original gap ledger was documentation-only. The subsequent native parity implementation is recorded below; the earlier 492 adapter/plugin/Host and 13 conformance passes in the [Claude audit](claude-support-audit.md) remain historical and do not verify the newly implemented paths.

| Gap cause | Meaning | Exit evidence |
| --- | --- | --- |
| Adapter gap | A concrete native operation/event exists, but the Remote adapter does not map it. | Adapter behavior, exact native acceptance/result, capabilities and consumer behavior verified. |
| Conditional native capability | Availability or semantics depend on native task type, permission, version or service. | Native eligibility discovered and rechecked at execution; unavailable paths stay explicit. |
| Cross-layer change | Directory, lifecycle, projection or configuration semantics need coordinated changes. | A design preserving ownership, recovery and public meaning, then tests across the affected endpoints. |
| Evidence gap | A faithful mapping has not been established. This does not prove native impossibility. | Native producer/consumer evidence and a bounded mapping before implementation. |

A row may have more than one cause. Delivery waves retain their original ordering. The delivery record below supersedes the initial gap classification where native probes established a stricter boundary. Preserve the baseline's S/C/P/N/U marks separately from these causes.

## Claude gap ledger

| Gap / baseline IDs | Cause and evidence | Implementation path and endpoint | Required acceptance / remaining boundary |
| --- | --- | --- | --- |
| G1 — live model and permissions, C1/C2 | Adapter gap. Paseo calls `setModel` and `setPermissionMode` [P-settings]; SDK also exposes `supportedModels`. | Claude settings adapter and Host model directory; reuse SDK settings and shared Web controls. Keep model IDs and permitted modes native-owned. | Reject stale/unavailable choices; confirm native success before publishing state; preserve permission mode across planning transitions. Launch/admin restrictions still apply. Debugger needs its own settings entry point (G19). |
| G2 — live reasoning effort, C1 | Cross-layer change. Paseo stores the new thinking option, marks `queryRestartNeeded`, and reports next-turn application [P-effort]. No direct `setEffort` was established in the pinned Query interface. | Prefer a public native effort setter if one becomes available. Paseo's idle Query replacement is a workaround, not this implementation's delivery target. | Prove identity/history continuity and failure recovery. Do not replace Query with active tasks or pending callbacks. Restart-on-next-turn is not a hot update; keep creation-only support until this is verified. |
| G3 — busy steering, I2/I5 | Native equivalence gap confirmed by the delivery record. Paseo captures the active Query/input/turn and submits `priority: next` [P-steer]. | Claude root input adapter; reuse `steer` and immediate-send semantics. Correlate message UUID, native consumption and terminal outcome. | Test turn-end races, stale target, unconsumed input, permission overlap, interruption and ambiguous acceptance. Never retry uncertain delivery or move a stale steer into another turn. |
| G4 — next-turn queue, I3/I4 | Evidence gap. SDK declares `priority: now/next/later` and interrupt queue receipts/capabilities; this alone does not establish our `next_turn` contract. Paseo's steering path is not a queue-parity proof. | First run a pinned native probe of delivery order, acknowledgements and queued-message cancellation; map native behavior only if equivalent. | Multiple queued messages, boundary races and interruption must have explicit outcomes. An interrupt may leave queued native input alive. No Host/Relay/browser scheduler workaround. |
| G5 — typed plan review, X3/X7 | Adapter gap. Paseo identifies `ExitPlanMode`, carries plan text and changes permission mode before allowing execution [P-plan]. | Claude pending-interaction adapter; reuse `plan_approval` and exact request correlation. Retain the original input and verified plan body. | Approve-and-resume, reject/feedback, native cancellation and duplicate answer. Define the post-approval permission mode explicitly; do not blindly copy Paseo's `acceptEdits` choice or invent missing plan text. |
| G6 — MCP forms and URL actions, X4/X6/X7 | Adapter gap with bounded semantics. SDK `onElicitation` carries form/url, schema and optional elicitation ID; `elicitation_complete` is a native event. This is SDK evidence, not a verified Paseo mapping. | Claude callback adapter; reuse current form/external-action schemas and Web cards. Share bounded schema-validation logic where semantics match Codex. | Reject unsupported constraints instead of dropping them; preserve sensitive handling and decline/cancel. Correlate native URL completion; prove whether callback acceptance and user completion are equivalent before exposing `completed`. |
| G7 — question sensitivity, approval scopes and granular grants, X1/X2/X5/X7 | Conditional native capability / evidence gap. Paseo passes native permission suggestions and `updatedPermissions` [P-plan]; arbitrary rule updates are not automatically filesystem/network grants. No reliable sensitive-question marker mapping was established. | Inspect each native suggestion's type, destination and lifetime. Map only exact supported tool scopes/policies; retain once-only behavior otherwise. | Never let labels define authority or widen scope. Typed grants need actual scoped grant requests. Shared redaction alone does not prove sensitivity coverage. |
| G8 — structured results and context/usage, T3/T4/T5 | Adapter gap for established fields; evidence gap for additional task/todo mappings. SDK has `tool_use_result` and `modelUsage.contextWindow`; richer fields do not imply every task tool is a todo list. | Claude projector and usage normalization; existing bounded tool-result and usage types. Audit SDK units/lifetimes before changing accounting. | Streaming/final dedupe, truncation, absent context size and multi-model results. SDK `total_cost_usd` is cumulative across a streaming Query while result `usage` is per-turn/main-loop: verify consumer expectations and difference/reset logic before treating them as one per-turn total. |
| G9 — output resources, R1/R2/T3 | Adapter gap plus resource-authority work. Native content can contain non-text outputs. Paseo workspace-file access is a different service [P-files]. | Claude session-owned resource registry and immutable bounded materialization; existing resource commands and renderer. | Define a concrete media subset; reject arbitrary paths and remote fetches; verify replay, disposal, limits and unavailable references. No upload support is implied. |
| G10 — skill body/provenance, C3/C4/C5/C6 | Evidence gap. SDK `SlashCommand` has name/description/argument hint/aliases, not an authoritative body locator. Paseo also classifies a flat list with limited provenance [P-skills]. | Establish trusted native lookup, or explicitly restrict filesystem discovery to configured sources with known precedence and identity. | Project/user/plugin collisions, reload, symlink/bounds and actual loaded version. A description is not a body; scanning `.claude/skills` alone is not complete discovery. Native commands do not imply Codex prompt-file grammar. |
| G11 — child task stop versus direct controls, A3/A6 | Conditional native capability. SDK `stopTask(taskId)` promises a stopped task notification. Paseo's Provider child panel is read-only [P-child]. | Probe root-owned task stop by exact parent/task identity. Only map to child `cancel` if its lifecycle matches that existing operation. | Saved/finished/unrelated tasks, races, parent loss and terminal notification. Stopping a task does not establish child input, reusable turn interruption, resume, or generic remote spawn. Keep those controls disabled independently. |
| G12 — missed child prefix and cold recovery, A4/A5/H2 | Cross-layer change. Current Host projection is append-only after history boundary; pending callbacks live in the original Query. | Improve collection before the boundary where possible. Any replacement/rebase of an established projection needs a separate recovery design. | No duplicate observations/receipts or silent timeline reordering. Re-pair cannot repair missing native facts; persisted history cannot recreate an old live approval callback. |

## Native parity delivery record

Implementation follows the native-client-first rule: public native methods and services are preferred; private runtime methods, Query replacement, synthetic scheduling and inferred authority do not count as support. See [validation and endpoint boundaries](provider-native-parity.md) and the updated [support matrix](provider-support.md).

| Gap | Current implementation / native finding | Remaining boundary |
| --- | --- | --- |
| G1 / G5 | Delivered through public Claude `supportedModels`, `setModel`, `setPermissionMode` and `canUseTool` plan review. | Idle settings; actual plan body required; restore the selected native permission mode before resolving approval. Cancellation does not release the setting mutation gate until native settlement. |
| G3 / G4 | Native negative probes: `priority: next` can start a subsequent turn; public `interrupt()` can retain queued input which later executes. | Both flags remain disabled. Private queue cancellation methods in bundled implementation are outside the public Query contract. |
| G6 | Ordinary public MCP callbacks work, but native client strips `pattern`, `multipleOf` and sensitivity markers before the callback while retaining defaults. | Forms remain disabled; the adapter cannot recover omitted source constraints. URL completion equivalence remains unverified; no external-action flag. |
| G8 | Delivered native structured tool results, Query cost increments, per-turn main-loop tokens and exact-model native context data. | Ambiguous multi-tool metadata omitted; no inferred occupancy or sum of context capacities. |
| G9 | Delivered root-owned embedded PNG/JPEG/GIF/WebP image references and immutable resource reads from native SDK bytes. | No filesystem/URL resolution, upload or child resources; explicit byte/count limits and unavailable results. |
| G13 | Delivered service-gated native direct-child catalog and non-activating live/saved history; modern plugin Host routing and exact parent/lifecycle checks. | Optional lookup failure cannot close parent; mutation/gaps rejected; no unowned native creation/resume. |
| G14 | Delivered cancel-only for live continuable children through synchronous native `interruptByParent`, after resident lifecycle validation. | ACK is admission, not quiescence; parent may be offline. Native FIFO remains parked and no completion is synthesized. Immediate send/steer are not equivalent; queue-only input needs a separate shared capability admission design. |
| G15 | Delivered model-specific reasoning choices through native `selectModel`. | Next-request session selection plus attempted deployment default save. Default-save failure is only exposed in native logs. |
| G16 | Delivered exact compaction start/end matching and success-only completion. | Failure/interruption is an error, not completed compaction. Current public items cannot replace the loading card with a failed terminal card. |
| G2 / G7 / G10–G12 / G17–G19 | Retain their individual evidence, authority, recovery and client-surface gates. | No inferred capability uplift from the new mappings. |


## Shared endpoint gaps and delivery order

**G19 — debugger entry points (C1–C5/I3/A1–A3):** headless and Lab support do not create CLI commands. Add command parsing, capability validation, correlation and bounded execution separately for settings/commands/queue/Host child attachment. The Provider adapter remains the native owner. Missing CLI affordances do not invalidate an otherwise working Web route.

**Shared boundaries (S3/T6/A6/H2):** Paseo does not establish that resuming a transcript attaches to an independently running native terminal, that a read-only child panel provides orchestration, or that replay reconstructs old callbacks. Generic native spawn/stop/resume, PTY control and durable callback recovery require their own scope and contract decisions. Generic file attachments, rewind and native forks are outside this matrix's implemented public surface; protocol 1.5.0 separately adds ordered raster image input for Codex and Claude. File services and client context transfer are not equivalent substitutes.

| Order | Candidate scope | Endpoint work and gate |
| --- | --- | --- |
| Wave 1 | Claude model/permission settings (G1), plan review (G5), steer (G3); DSH read-only children (G13), effort (G15), compaction (G16). | Adapter plus relevant Host/plugin directories, capability-driven shared UI and isolated native/transport probes. Existing protocol paths are the starting point; any discovered semantic gap gets explicit review. |
| Wave 2 | Claude forms/URL actions (G6), structured results/usage (G8), bounded resources (G9); DSH continuable child controls (G14). | Validate identity, authority, schema subsets and lifecycle before enabling each flag. URL completion and child controls can remain unavailable if equivalence fails. |
| Research gates | Claude effort restart (G2), queue (G4), richer permissions (G7), skill provenance (G10), task stop (G11), history recovery (G12); DSH creation (G17) and unmapped native features (G18). | Produce a native behavior record or a concrete cross-layer design first. A failed equivalence probe is a documented bounded gap, not a reason to emulate semantics. |
| Independent client work | Debugger operations (G19). | Implement only supported public operations; test against real transport and record CLI coverage separately. |

For each implementation, update the linked baseline IDs only after relevant tests pass. Record actual SDK/native versions, per-test and outer deadlines, fixture versus live execution and remaining limitations. Use the [onboarding checklist](provider-onboarding.md); regenerate/check compatibility metadata when the implementation or degradation record changes.
