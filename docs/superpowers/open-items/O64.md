# O64: The E3 flow 'a session the Host no longer has…' fails about one run in three

- Found in: the 0.3.4 release gate and the module split's end gate, 2026-11-22
- Owner step: owner
- Status: closed

## Item

`flows/e3-reconnect-and-return.e2e.ts` > "E3: a session the Host no longer has shows as an empty view that says so, and a new session opens beside it" waits 20 s for the status "“Gone” no longer exists on E2E Host" after the Controller restarts without the session and the page reloads, and times out. It failed once in the 0.3.4 release gate (recorded beside O60 in the release record) and once in `pnpm test:e2e:flows` at the end of the module split (`52dfa735`; 63 of 64 passed). Run alone it fails 2 of 6 times at this branch's base (`674195a3`) and 1 of 3 at `52dfa735`, so it is not a regression of the split. Not investigated: whether the reloaded page asks for the session before the restarted Controller has registered with the Relay, so that the attach fails as offline rather than as missing and the view waits for the Host instead of saying the session is gone

## Status

closed (2026-11-22). Not the product and not a clock: the flow raced the page. The page creates its Window with the session named as its link named it ('Session') and retitles the view once the Relay has confirmed the Window and the catalog the title, a moment after the conversation paints. The flow stopped the Controller as soon as the answer painted, so under load the reload came before the retitle: in a failing run the Relay's Window still held 'Session' and the page said "“Session” no longer exists on E2E Host". The flow now waits until the Relay's Window holds the title 'Gone' before the Host loses the session. It passed 10 of 10 runs beside the Workbench unit suite
