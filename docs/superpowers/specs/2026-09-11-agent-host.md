# Agent Host

The agent side supports two forms: a plugin embedded in a native runtime such as DSH, and an independent Agent Host daemon managing CLI runtimes. The workbench backend brokers connections and never launches production Codex processes. Dedicated Providers translate native APIs into the existing normalized Remote events. Codex uses app-server. A future ACP Provider can supply baseline capabilities for ACP-compatible CLIs without replacing dedicated Providers; no ACP implementation is required here.

Host owns runtime lifetime and a provider-scoped session directory. Runtime and session are different identities: native Codex children borrow their parent's connection. Closing a browser or disconnecting the uplink must not dispose runtime sessions. Reconnecting reuses native sessions and observations, and uncertain operations are never blindly replayed. A daemon restart restores only what native persistence supports; ongoing turn recovery is not promised. Temporary pairing credentials remain backend-process-local.

A Host advertises one or more provider descriptors. Discovery, workspaces, model queries, create, attach, and native child attach carry provider identity all the way to the Host. Creation returns the native ID chosen by the runtime, not a broker guess. Host independently deduplicates creation requests. Existing DSH uplinks remain supported. Public session protocol 1.4.0 and normalized event semantics remain unchanged; extend only the uplink registration/directory envelope where needed.

The console lists actual paired machines and their providers. Recorded fixtures remain a clearly labeled local test source, not an always-online machine with production Codex. Existing chat controls, child sessions, fork, and side chat continue to work through the Host route. Browser-owned context-fork preparation is not moved by this runtime extraction; its existing normalized input still travels through Host. No new scheduling, queues, or synthetic subagents are introduced.

Provide runnable foreground and daemon commands with pairing guidance, stable installation identity, scoped configuration, status/stop, bounded startup/shutdown, and logs. Preserve existing services and user runtime files. Validate with real transports and a real Codex binary against an isolated deterministic response endpoint; separately identify any unverified live model endpoint or native DSH run.
