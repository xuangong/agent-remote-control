# Docker Host bootstrap

Users enroll a Docker Host using an existing Agent Remote pairing key. The container exchanges it for a durable device credential, asks the authenticated Relay for a dedicated Gateway LLM key owned by the same account, writes an isolated Codex configuration, and starts the normal Host. No Google login is used in tests.

Gateway service API: POST /api/agent-remote/host-key and /api/agent-remote/revoke-host-key, existing arc-relay-service+jwt body-bound proof. Input {subject, hostId, hostName}. Issuance returns {apiKey, keyId, baseUrl, model}; baseUrl is issuer + /v1 (verify against actual routing before finalizing), model configurable via AGENT_REMOTE_CODEX_MODEL with a documented default. Gateway keeps stable owner/relay/host binding, handles concurrent bootstrap without extra keys, and never recreates a deleted/revoked key automatically. Ordinary Gateway key rotation is reflected on the next bootstrap. Disabled/unknown accounts are denied.

Relay POST /v1/remote/host/bootstrap accepts only a current durable Host bearer device credential, no cookie/origin credentials, no caller-supplied owner or Host ID. Resolve identity from broker state, check owner authority, sign Gateway request and return bounded validated credentials with no-store. Invitations and revoked devices cannot obtain keys. Owner Host revocation also revokes its Gateway key before deleting the Host; failure leaves a retryable operation.

Controller opt-in AGENT_HOST_BOOTSTRAP_CODEX=1 (Docker default). A short-lived registration using the stable installation ID persists the rotated device credential before requesting bootstrap. Close it before starting the normal Host. Bootstrap must not overwrite user Codex files; use a dedicated managed CODEX_HOME and private files. No keys in image layers, command arguments or logs. Persistent volume holds Host/Codex state; workspace is separate. Runtime is non-root, foreground, proper signals, locale C and nofile 8192. Existing standalone pairing remains independent of Gateway.

Validation: true SQLite migration and route tests; real Relay HTTP/WebSocket with simulated local accounts; build/run Docker with Codex installed; use temporary test accounts/databases and free ports, preserve existing services. Read-only inspect localhost:41414 and, if usable, send a minimal real native Codex request through its existing upstream. No push, deploy, or production account modification in this task.
