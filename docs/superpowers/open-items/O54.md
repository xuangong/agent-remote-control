# O54: In WebKit the page stays empty when the first fetch of the code-split `App` chunk fails

- Found in: e2e convergence
- Owner step: owner
- Status: closed

## Item

In WebKit the page stays empty when the first fetch of the code-split `App` chunk fails: WebKit does not fetch the refused chunk again, not even after `loadChunkWithRecovery`'s reload ('Importing a module script failed'; no request for the chunk after the reload). It fails the same at `4c301368`; E3's O27 flow now runs in Chromium only. Not checked in a real Safari, so it may be WebKit's handling of a route-fulfilled 502

## Status

closed (2026-11-22): real WebKit behaviour, not the route: WebKit keeps a failed `<link rel=modulepreload>` response for its URL across reloads and navigations (reproduced against a plain server), and Vite preloaded the App chunk itself before importing it. The build emits no JavaScript modulepreload links (`build.modulePreload: false`; CSS is still loaded by the preload helper), so a failed `import()` is fetched again after the recovery's reload. E3's failed-chunk flow runs in WebKit again and fails with the preload back on
