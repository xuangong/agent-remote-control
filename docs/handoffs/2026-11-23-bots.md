## 2. What the deployment gives the person

- **One kind of bot.** Every bot has a Relay record (stable id, name, label, picture, **mission**, organizer) and the same tools:
  `create_bot` (temporary or standing), `message` (with `status`), `list_bots`, `read_bot`, `update_mission`, `stop_bot`,
  `retire_bot`, the room tools, and Call For Support until its fold. No coordinator or plain mode.
- **Bots create bots.** A temporary bot works on one piece of work and reports to its organizer with `message` (`done`, `failed`,
  `needs_input`, `progress`); results arriving during a turn reach the organizer as one input. A standing bot created by a bot
  starts with its standing instructions and tools, joins its organizer's group in Chats, and reads its first message.
- **Inboxes.** Messages between bots, and standing instructions, reach a bot between its turns, at most once. A bot with a mission
  gets its instructions when they change; a bot without one with the first message another bot sends it, so a deployment wakes no
  bot by itself.
- **The mission** is written in the bot's details; a bot records lasting changes in its own mission.
- Existing bots move into records when the Relay loads its state.

## 4. Deployment

1. Relay first: it migrates bot records on load. Forward only: an older Relay cannot read a state with `bot` records.
2. Then every Controller: a Controller older than the stack sees no inboxes and gets no bot tools; nothing breaks for it.
3. Before pushing, from `main` after the merge: `pnpm postmerge` (compatibility digest, open-items index, budgets).

## 5. Known limits, after the first deployment

- Claude Code ignores instructions appended on resume, so standing instructions reach a bot as a message (design 5.1).
- A resumed Claude Code session keeps the schema of a tool it loaded through tool search before the tool changed (seen when
  `create_bot` gained `lifetime`); new sessions, and tools it never loaded, get the current schema. Existing bots have never loaded
  the bot tools, so the first deployment is not affected; later schema changes are.
- Not built yet, each only adding to the tools: replies from final text for bots whose provider takes no tools (OpenCode, DSH);
  attachments with git bundles; telling an organizer what the person wrote to its standing bot.
- A temporary bot's inputs are still framed `[Task …]`; the page shows them as task cards.
- Room and bot timers run on the Relay's in-process timers. A hosted Relay arms them again when it loads the account (a Host
  reconnects, or the person opens the page), so a timer due while the Relay object was evicted fires then.
- Call For Support, Team, Side and TPM are unchanged until their folds (plan step 7); the Workbench of the model is plan step 6.
