# O49: A Claude Code page turn and a terminal turn at the same time fork the transcript

- Found in: M6
- Owner step: owner
- Status: closed

## Item

A Claude Code page turn and a terminal `claude --resume <id> -p` turn at the same time fork the transcript, and the page and the native session then disagree for good: the page shows its own branch and `session read` the terminal's (or the page's, with the terminal's turn gone). The S6a divergence release does not fire, because it counts a transcript as diverged only when it changed more than 2 s after the Controller's last write, and two turns that end within 2 s of each other pass that check (2026-11-21 03:04 to 03:11: after 190 s the page showed PAGE1Y and PAGE2Y, native history TERM1Y and TERM2Y)

## Status

closed (2026-11-22, step 5 of the provider boundary), as a generic policy keyed on the declared concurrency model `fork_on_divergence`, not on the provider id. Root cause: divergence was decided by time, a native update more than 2,000 ms after this process's last write, so two turns that end within 2 s of each other never counted, and the resident session kept its own branch while native history showed the other. Now divergence is decided by content (`transcript-divergence.ts`): a quiet resident session is diverged when its transcript, as a new attachment would read it, holds a record the session neither read at load nor wrote since, or its newest record is not the session's last one. The Claude adapter tells the conversation records a session holds (`nativeState().records`: read at load, sent, and the stream's main-chain rows, not a synthetic row or withdrawn input) and reads the transcript's records in its catalog worker (`transcript-records`, uuids only); the stdio directory keeps each verdict while the transcript's update time and the held records are unchanged, so a transcript is read once per change. A diverged session is released and read again before a send (as before), at the next listing when nothing holds it, and, new, at the next listing when a page shows it: it is released and attached again at once, so the page follows native history without a send. Claude Code still coordinates no writers, so one branch is lost whatever we do; the page now shows the branch native history shows, whichever ended last. Pinned in the CLI simulator with turns ending 0, 1,999 and 2,001 ms apart (`transcript-fork.test.ts`, the O49 expected failure is a plain test) and by the content rule's vectors. Every Controller must update
