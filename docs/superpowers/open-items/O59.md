# O59: The page compares the Relay's absolute lease expiry with the device's clock

- Found in: gap 7
- Owner step: owner
- Status: closed

## Item

The page compares the Relay's absolute lease expiry (`expiresAt`) with the device's clock (`GatewayController.tsx`): a device clock ahead of the Relay's by more than the lease's life makes every access answer look expired, so the page pauses its sessions and asks again every few seconds. Found by the browser lifecycle simulator when a resume moved the page's wall clock 10 minutes ahead (the simulator now keeps the wall clock real); a phone set to the wrong time meets the same

## Status

closed: `leaseDeadlineOnDeviceClock` in `packages/agent-remote-lab/src/kernel/lease-clock.ts` turns the answer's absolute `expiresAt`, the Relay's own time (the response's `Date` header) and the device time at receipt into the lease's deadline on this device's clock. A skew up to 5 s (header resolution of 1 s plus latency) is ignored, so a device that agrees with the Relay keeps the Relay's `expiresAt` exactly; a larger skew moves the deadline by the skew; a missing or unparseable header means no correction; a lease already ended on the Relay's clock stays expired. `GatewayController.tsx` computes the deadline right after parsing the answer and uses it for the expired-answer check, the expiry timer, the confirmation of an expired lease, the unavailable path and the hidden-page renewal, and stores it as the display lease, so a reload compares it with the same clock. No Relay or protocol change: the Node relay and Cloudflare already send `Date`. Held by the vector table `kernel/lease-clock.vectors.ts` run in `kernel/lease-clock.test.ts`, and by two `GatewayController.test.tsx` cases (device 10 minutes ahead becomes ready without asking again; device 10 minutes behind still renews before the real deadline).
