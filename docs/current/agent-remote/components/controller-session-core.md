## Purpose
- C1. The core binds each native session once to a public agent id, gives it a runtime on demand (attach), keeps it while anyone holds it, and releases it after an idle grace, journal first, then runtime, then directory.
- C2. Control requests (`/remote/...`) from the Relay and the local command line enter through `control`, which parses, admits, routes and answers them; the core owns no session state beyond bindings, idle entries and the start backoff.

## Inputs and outputs
- C3. `parseCreateRequest` takes a provider, an operation id and a proposed identity (request `sessionId`); a creation source is the explicit one or the legacy source read as one of the same provider. `parseAttachRequest` takes proposed identity, provider and native session; a child attach also needs its parent; a takeover needs a UUID owner generation.
- C4. `project` binds and attaches a session once: it reuses a live runtime whose creation evidence matches, otherwise opens the native session, annotates it and registers it with the Relay's runtime; the answer is the binding without its provider (`publicBinding`).
- C5. `acquireSession` returns a lease that releases the runtime and its parent exactly once; it holds the parent of a child first, waits for a release in progress, and re-reads a diverged quiet session before a send continues from it.

## States and transitions
- C6. Admission has three states: `open`, `draining` (refuses `POST`/mutations with `controller_updating`, reads still answer) and `closed` (refuses everything with `host_closed`, never reopens). `beginDrain` works only from `open`; `cancelDrain` returns draining to open; `close` always ends closed (`admission.ts`).
- C7. A binding is made once per native session; while it is made the native session is pending and the agent id reserved; afterwards the agent id stays reserved; a bind after `close` is refused (`bound-sessions.ts`).
- C8. An idle session is released only when the Controller is open, the session is certain (no unsettled operation, no unfinished family check), its binding is complete, its directory allows it, its runtime says it can be released idle, and no child bound under it has a runtime or a holder (`mayReleaseIdle`, `hasHeldChild` for one provider only).
- C9. An uncertain session is reconciled first (directory can reconcile, runtime releasable, no held child); a successful check clears the uncertainty but never settles or replays the unknown operation (`mayReconcileIdle`, `attachment.ts` `watch`).
- C10. Transcript divergence (O49), for a CLI that declares `fork_on_divergence`, never by provider id: a quiet resident session is diverged when its transcript, as a new attachment would read it, holds a record the session neither read at load nor wrote since, or its newest record is not the session's last one, however close in time the writes were; a diverged session may be released only when nothing runs for it and its transcript was quiet for 30 s (`DIVERGENCE_QUIET_MS`); a diverged session is released and read again before a send continues from it, at the next listing when nothing holds it, and at the next listing, attached again at once, when a page shows it (`transcript-divergence.ts`, wired in `stdio-directory.ts` as `checkDivergence`, `divergedAt` and `canReleaseSession`, and in `terminal-refresh.ts`).
- C11. Idle grace: a session no page shows, with no lease and a safe state, is released after its release grace (C22; `graceMs` replaces it when the Controller is configured with one, default 5 minutes, `idle-sessions.ts`); every lease, touch, reconnect, unsafe observation or change of what pages show restarts the full grace; the grace is suspended while the uplink is disconnected; a returning lease waits for a started release and never causes a second release; a failed release retries after a new grace.

## Limits
- C12. `graceMs` and `reconcileMs` (default 60 s) must be positive safe integers, else `RangeError` (`idle-sessions.ts`). Reconcile backoff doubles per failure, capped at 10 failures and 15 minutes; one reconcile runs at a time.
- C13. A creation source identity and each edit identity are at most 256 characters (`requests.ts` `parseCreateRequest`); a canonical identity chosen after a qualified source create must pass `boundedSourceIdentity` (non-blank, at most 512 characters) or the attach fails (`attachment.ts`). A rename title is at most 512 characters, no control characters.
- C14. Native start backoff: a recent native start failure is repeated instead of starting again until it expires; an explicit takeover always tries (`control-routes.ts` with `native-start-backoff.ts`).

## Errors and refusals
- C15. Every malformed request is a `HostRequestError` 400 `invalid_request`; nothing is read from a request before it is validated; unknown routes and non-JSON bodies are refused.
- C16. `failureResponse`: typed errors keep their status and code (a session in use keeps the CLI's `reason` and `retryAfterMs`, O48; a runtime failure keeps a usage limit's `resetsAt`, gap 3); a failed GET is `catalog_unavailable`, a failed attach `session_attach_failed`, anything else `mutation_outcome_unknown`; generic answers carry only the class and code of the cause, never its text. `operationErrorStatus`: conflict 409, capacity 429, unknown outcome / closed cache / native file limit / bad clock 503, others 400.
- C17. A provider returning another native identity is closed and refused; a Controller that closed meanwhile disposes what it opened and answers 503 `host_closed`; a disabled provider is refused with `provider_disabled` unless the session is already live under the same identity (uplink recovery).
- C18. Diagnostics (request diagnostics, `session_idle_*` lifecycle events) can never fail a request or change a session's lifetime; a request diagnostic carries a digest of the native session id, never the id.

## Guarantees
- C19. `all` lists bindings in the order made and is a snapshot; `family` is the session, its children and grandchildren of one provider, in bind order; `live` omits bindings with no runtime; `bindingOf` throws `invalid_operation_target` for an unbound runtime.
- C20. A release goes in the order journal, runtime, directory, and a restored session keeps the same binding; a repeated attach keeps one projection; a stop cancels every live session and reports cancelled, unsupported and failed apart, bounded by the cancel deadline.
- C21. Residency (`session-core/residency.ts`, O47): a session a page shows is kept whatever else is true of it; one an operation or a Controller stream holds, or that cannot be released now, is kept; one that nothing keeps waits its whole grace from the last moment something kept it and is released at the grace, not before. A shown session counts as demand: the terminal refresh leaves it alone and `expire` does not end its grace.
- C22. The release grace follows the provider's declared behaviour, never its id: a CLI that keeps a session loaded after its last client (`unloadAfterLastClientMs`) gets the page-return grace, 10 s, so Codex unloads a session within 80 s of the last page closing; otherwise a subscription 15 s, a shared process 60 s, a process of its own 5 minutes (also an adapter that declares nothing).
- C23. The shown set (`session-core/shown-sessions.ts`) is the complete set the Relay last sent (`journal_shown`); it replaces the one before, marks every bound session, and is applied to a session bound later when it is attached.
- C24. Resume deadline (gap 4, `session-core/resume-deadline.ts`): an open, or a child's, that the CLI does not answer within the deadline its adapter declares (`behaviour.resume.deadlineMs`, never the provider id) fails at the deadline with the typed `native_unresponsive` (503) and frees the binding; a session the CLI hands over later is disposed. A take-over is not timed. The next open is then held only by the native start backoff (C14).
- C25. Turn watchdog (gap 4, `session-core/turn-watchdog.ts`): for an adapter that declares no turn heartbeat (`behaviour.turn.heartbeatMs`), a turn whose CLI emits nothing for `TURN_SILENCE_MS` (15 minutes; every item restarts the watch, the turn's end stops it) ends with `turn_failed` code `native_unresponsive`, the session reads idle, and the runtime is released (journal, runtime, directory, as C20), so the next send attaches the session again. Limit: a command silent for longer is taken for a hang.
- C26. Native exit (`session-core/native-exit.ts`): a CLI that exits under a session (a turn failed `native_exited`, the typed failure, or a stream that ends or fails without the Controller disposing the session) has its runtime released once, after the failure reached the readers with the CLI's reason; the next send or open attaches the session again from native history within the declared resume deadline, and nothing the exit cut off is sent again. Keyed on the failure taxonomy and the SDK's stream contract, never on a provider id.
