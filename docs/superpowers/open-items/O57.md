# O57: A multi-line message sent before E2's offline case leaves the offline message waiting

- Found in: e2e convergence
- Owner step: owner
- Status: closed

## Item

On one stack, a multi-line message sent before E2's offline case leaves the offline message at 'Sent — waiting for conversation…' although its echo is in the timeline (5 of 5 runs; it passes alone, and with a single-line message instead). Client echo matching or the flows' WebSocket route; the multi-line flow has its own file meanwhile

## Status

closed (2026-11-22): a harness defect, not the product and not gap 5's mechanism. The e2e scripted provider keys a row by its place in the session's history, and a streamed reply reserved its place but entered the history only when it completed; a message written while it streamed (700 ms) took the same key, and the reply's later pieces overwrote that user row, so the page never saw its echo. The multi-line flow proceeds on the reply's first half, which holds the text it waits for, so the offline message of the next flow landed inside the stream; a single-line reply is only complete after both halves. The streamed reply now takes its place as it starts. Reproduced with both flows on one stack (failed, then passed with the fix); pinned by `stack/scripted-provider.test.ts` > "gives a message written while a reply streams a key of its own, so the reply never overwrites its row (O57)", which fails on the old provider
