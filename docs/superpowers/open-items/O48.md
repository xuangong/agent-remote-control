# O48: When Codex refuses the Controller because a separate process writes the session, the page shows none of its rows

- Found in: M6
- Owner step: owner
- Status: closed

## Item

When Codex refuses the Controller because a separate process writes the session, the page shows none of the session's rows, no activity, and "Native CLI has control" with "Interrupt & take over" (the old private-writer takeover, which stops that process) instead of Codex's reason and a Retry; once the process ended, its turn did not reach the page within 90 s (2026-11-21 03:24:59 to 03:27:40, `.tmp/m6/separate.log`)

## Status

closed (2026-11-21, step 4 of the provider boundary), as a generic policy keyed on the declared concurrency (the typed refusal `AgentSessionInUseError` with `reason: 'writer_elsewhere'`), not on the provider id. Root cause: the Codex directory turned Codex's single-writer refusal into a native owner with the private-writer take-over (`native_session_owned`), the attach refusal kept the page from opening the session at all, and no frame said why. Now: the Controller answers 409 `session_in_use` with the CLI's reason and wait; the Codex directory no longer offers the take-over; the Relay answers the attach of a session it reads from its journal with the binding, keeps the refusal per binding and tells every page in `session_control` (`nativeRefusal`, read-only), whose Retry (an acquire) asks the Controller again; an attach that succeeds clears it and the CLI's turn reaches the page. The page words it as the active writer of its CLI, with Retry and no take-over (client presentation R6). Pinned by the CLI simulator (`agent-remote-seams/tests/S2/writer-elsewhere.integration.test.ts`, 2 tests), `broker-native-refusal.test.ts`, the session control rows and the presentation row. Not done: a read-only observation of the native history while the writer is elsewhere (`reread.withoutAttach` is declared false for Codex until a native check), so the page shows the journal as it was until the retry; the explicit Codex take-over path stays for a request that names an owner, which no page is offered now. Was open: the journal-served stream refuses the page when the attach at open is refused (`recoverForJournalStream`), although reads need no Controller; the Controller maps Codex's "active writer" to `native_session_owned`; nothing observes the session read-only meanwhile. M6 reports `page-stays-live-when-codex-refuses` failed. Needs a Relay and Controller release and a protocol error with fixed copy for Codex's reason. Reproduced in the CLI simulator (step B2, 2026-11-21) as an expected failure: `agent-remote-seams/tests/S2/writer-elsewhere.integration.test.ts`
