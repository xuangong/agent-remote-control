# M5 to M7: where the rules and their tests went

Companion of `2026-11-18-target-architecture-and-tests.md`, steps M5, M6 and M7. For each step: the module and its contract, the tests that own the rule now, the mutation check that justified each deletion, and the change scope before and after. A mutation is a one-line break of the rule in the module; a deleted test must fail under at least one mutation that also fails the new tests.

## M5 Journal window decision (X3)

**Module.** `agent-remote-journal/src/window-decision.ts`: `decideWindow(tail, window, room?)` is a pure function that returns `unchanged`, `extend` or `replace` with a reason. Its contract is written in the file and in `seams.md` (S2, "Window decision"). `SessionJournal.sync` and `extensionBytes` call it; `SessionJournal` keeps the writes. The client's side is `agent-remote-web/src/replica/window-absorption.ts` (`absorbWindow`, moved out of the reducer, no logic change).

**Vector table.** `windowVectors` (47 rows, journal `./testing`) with three consumers, one line each: the journal (`window-decision.test.ts`: `decideWindow` and `SessionJournal.sync`, 94 tests), the Controller publisher (`journal-window.contract.test.ts`: the window `windowOp` builds from timeline items with its own digests, 41), the client replica (`seams/S3/window-absorb.integration.test.ts`: `absorbWindow`, 47). The table lives in the journal and not in `agent-remote-fixtures`: the fixtures package depends on the journal, and a journal test importing it would close a dependency cycle. Web does not import the journal: its consumer is the S3 seam suite.

**Deleted (22).** 21 tests of `journal-sync.test.ts` (the decision restated through `sync`: digest, missing, moved, new-inside, open versus complete, incomplete, empty window, further back, long window, item before the first shared key, leading live-only, no shared key, live-only skip and append, equal board, new live-only key, live-only content that cannot be rewritten, open content, open without a body, extension fits, extension does not fit, and the four reason tests) and the absorption half of one reducer test (`reducer.test.ts`, the epoch and retirement half stays).

| no check before the first shared key | 3 | 1 journal |

Not mutation-proven, so kept: the old test for a key that is live-only in one place and native in the other. The guard that returns `changed` for it is shadowed (the native comparison returns `changed` first), so no mutation of that line fails any test; the new vectors state the outcome. The `state === 'complete'` test in the digest comparison is likewise equivalent to the digest test.

Kept on purpose, not duplicates: the Relay's host-journals window tests (events to subscribers, diagnostics, quota and refusal behaviour), the Controller's recording-driven continuity tests (the S2 proof the spec names), and the real-socket `journal-served-reconnect` test, which tests paging after an in-place update, not the decision. The spec's "six real-server variants" do not exist in this checkout: there is one.

**Scope.** A change to the window rule selected, by package, the journal and its dependents: Controller, Relay core, debugger, fixtures, seams, Workbench, Cloudflare, SQLite store (about 6,100 tests at the baseline; the Workbench and the Controller alone are 85 s and 74 s). It selects now the vector table and its three consumers plus the S2 seam: 99 + 41 + 47 + 4 + 16 = 207 tests, each file under 20 ms, 1.5 s with start-up. The package-level `verify:changed` still selects the dependents; the module-level plan (section 5.9) is what makes the small scope real.

**Exceptions.** None lowered. The `domain-impure` entry for the journal (`crypto.randomUUID` for epochs) was owned by M5 but needs the Relay's `Ids` port; its owner is now M11.

**Smoke (`pnpm smoke:quick`, seed 91788, build 8a0d831a642a).** M2 passed (7 invariants: one replacement per restart 2, sequences contiguous 14, messages settle once 4, no duplicate key 48, no blank frame 45, no stale label 4, turn rows complete 4). M7 passed (catch-up one tail request 2, no stale label 15, draft and position kept 2, no blank frame 40, no duplicate key 30, half-open recovers 1). M1 failed on `first-paint-from-device-store` as at the baseline (4.6 s Claude, 4.9 s Codex at 300 ms and 2% loss against 3.3 s; the loss draws differ with the seed); M8 owns it.

## M6 Relay session control (X2)

**Module.** `agent-relay-core/src/domain/session-control/session-control.ts` (module `relay-session-control`, layer 1, under the domain-impure ban): `transition(state, event)` returns the next state and a reply as data; `viewOf(state)` is the `session_control` payload. Ids come with the events (`fresh`). The contract is written in the file and in `seams.md` (S3, "Lease table"). `stream-control.ts` is the shell (decode, mint ids, ask the Controller who holds the session, send replies); `createStreamControl` behaves as before. The lease code was already one closure in `stream-control.ts` (S5 had moved it out of `broker.ts` and `journal-sessions.ts`), so the move is the state machine out of that closure, about 60 lines, not the 250 the spec estimated.

Client: `agent-remote-web/src/client/lease-view.ts`, one table from the replica's control state to `readOnly`, `checking`, `native` and the words of the read-only notice and the activity line; `remoteSessionState`, `SessionControlNotice` and `SessionWorkbench` read it. There is no refusal-to-view mapping in `remote-session-client.ts` to move: refusals reach the replica only as the control state.

**Tests added.** 27 table rows and 6 more over purity, owner copying and the view (`session-control.test.ts`); 10 shell tests (`stream-control.test.ts`); 6 rows of the lease view table. Each under 20 ms. The S3 lease transcripts (acquire, stale revision, send without a lease, native owner refuses, offline Host) replay unchanged through the new shell (the S3 suite, 18 tests).

**Mutation check** (13 mutations of the table: no revision check, token reissued, owner kept on acquire, mutation always passes, an absent token passes, token kept after a refusal, owner never named, stale holder accepted, snapshot always announces, view ignores the owner, any code counts as ownership, revision kept on refusal, `available` always true): every mutation failed the new table or shell tests (1 to 7 each). The old tests that failed with them were 8 in `journal-session-stream.test.ts` and `broker-journal-sessions.test.ts`, plus 4 resource-budget tests of `broker.test.ts` that only fail when every mutation is let through; the S3 seam failed 0 to 5 per mutation. Client mutations (checking counts as read-only, the two owner labels swapped, control counts as read-only): the new rows failed, and so did 6, 1 and 144 Workbench and composer tests that render the state (they test behaviour: queueing while checking, the draft staying focused, the takeover words).

**Deleted.** No whole test: the old tests that fail under a lease mutation are stream integrations (they open a Controller stream, forward frames, hold operations). Two lost their lease assertions, which the table owns: the stale-revision, forged-token and read-only assertions of the first and the re-acquire sequence of the second (15 lines), keeping the assertions on the stream wiring (the Controller is never opened for a refused mutation; the owner is shown when opening is refused). The spec estimated about 30 tests; the checkout does not have them. The lab `session-control-transport` test (real transport) and the Controller's owner check at delivery (`relay-session-control.test.ts`) stay, as the spec says.

**Scope.** A lease rule change selected the Relay core package and its dependents (Controller, debugger, fixtures, seams, Workbench, Cloudflare). It selects now the table and the shell (43 tests, 0.3 s) and the S3 suite (18 tests, 0.5 s); a client change selects `lease-view.test.ts` (6 tests) and the renderers that read it.

**Exceptions.** None lowered; the Relay core exceptions are owned by M11.

**Smoke (seed 33512, build 39bb5c0f1aac).** M2 and M7 passed, every invariant as at the baseline; M1 failed on first paint from the device store as at the baseline (3.3 s Claude, 3.9 s Codex), owned by M8.

## M7 Send-state machine (X8)

**Module.** `agent-remote-web/src/replica/send-state.ts`: `transition(state, event)` over `sending`, `awaiting_echo`, `unconfirmed` and `failed` with the events `acknowledged`, `send_failed`, `echoed`, `history_changed`, `restored` and `retry`; `describe(state, delivery)` for the words; `canSettle`, `awaitsEcho` and `retriesSameOperation`. The spec's names `idle`, `pending`, `queued`, `delivered`, `uncertain` map onto what the code has: no message before send, `sending` and `awaiting_echo` (words "Sending…", "Sent — waiting" and, for a next-turn delivery, "Queued — waiting"), a message leaving the list as `delivered`, and `unconfirmed` for uncertain. Contract: written in the module and in `seams.md` (S6, "Send state"). `message-outbox.ts` is renamed `pending-messages.ts` (class `PendingMessages`; `resource-message-outbox.test.ts` follows).

**Code moved.** The scattered status rules went into the table and its callers read it: the acknowledgement, restore and retry rules of the replica store, the echo and history-rewrite rules of the pending-message reconciliation, the failure words and the retry, delete and same-operation guards of the session client, the delivery words of `OutgoingMessageItem`, and the list of stored states in the Workbench's `message-recovery.ts`. `recovery-writes.ts` is storage scheduling, not send state, and stays; the composer's pending-send queue (`usePendingSend`, phases waiting to error) is a separate machine for messages that wait for a connection, and also stays. The moved logic is about 80 lines, not the 400 the spec estimated.

**Tests added.** 26 table rows, the who-may-retry, same-operation and word tables: 42 tests, each under 20 ms.

**Mutation check** (12 mutations: an acknowledgement lifts `unconfirmed`, an acknowledgement changes `failed`, an echo settles `failed`, a history rewrite resets `unconfirmed` or touches `failed`, a reload turns `failed` into `unconfirmed`, any state may be retried, uncertain counts as failed, a retry ignores the place, the next-turn label, a handled command stays, the order of the failure words): each failed the new table (1 to 3 tests). Old tests failed under only three of them: uncertain counted as failed (6 behaviour tests of the session client and the composer transport), a retry ignoring the place (1), and a handled command kept (1); the Workbench tests filtered to messages and recovery (214) passed under every mutation. So the rules were largely unpinned before; the table adds coverage and removes none.

**Deleted.** None. The 25 tests the spec expected in web, lab and four e2e specs are not duplicates of these rules: the old tests that failed are behaviour tests (a real channel reconnect, a late echo after a generic failure, the same operation identity on retry), which stay. `pending-send.spec.ts` is one test per target about the composer's send-later queue, not about this table, so it stays.

**Scope.** A change to a send-state rule selected the client package (1,008 tests) and its dependents, the Workbench included. It selects now the table (42 tests) and the view test `OutgoingMessageItem.test.tsx`, which is the S6 pending-send view test until the client split gives S6 its own suite.

**Exceptions.** None lowered.

**Time.** The table runs in 0.12 s, the view test in 0.7 s (jsdom start-up).

**Smoke (seed 7284, build 001505084eef).** M2 and M7 passed with every invariant as at the baseline (messages settle once 4 in M2 and 2 in M1); M1 failed on first paint from the device store as at the baseline (3.9 s Claude, 3.7 s Codex), owned by M8.

## M8 Split the client; first paint; S6 and S7

**Packages.** `agent-remote-web` is gone. `agent-client` (headless, `node` environment, no React or DOM) holds `client/` (connection, session client, transports, lease view, window and activity clients), `replica/`, `device-store.ts`, `session-record.ts`, `display-lease.ts`, `page-lifecycle.ts` and the `./testing` entry (builders, `buildReplica`, `replicaAfter`, `memoryDeviceDatabase`, the device database cases, `stubBrowserPage`). `agent-client-web` holds `react/`, `browser.ts`, the IndexedDB database, the browser binding (`page/browser-environment.ts`), `image-drafts`, `resource-drafts` and `styles.css`. Two ports make the split a graph fact: `PageLifecycle` (hidden, visibility changes, resume and suspend; inert by default) and `DeviceDatabase` (`readIndex`, `read`, `write` of one batch, `clear`). Importing an `agent-client-web` entry installs both. The HTTP/WebSocket transport stays in `agent-client`: the debugger CLI uses it in Node, and it takes `fetch` and `WebSocket` as options. The replica reducer (684 lines) is `snapshot-apply`, `live-fold`, `page-fold` and `entry-algebra`; `reducer.ts` re-exports the public names, and `window-absorption` and `pending-messages` were already their own modules.

**First paint.** Smoke found that the first rows of a revisit came 3.3 s after the page opened at 300 ms. Causes, in order of weight: (1) the revisit had no record. The probe closed the first page within the device store's 50 ms write-behind delay, so IndexedDB was empty (checked); the cached lease was valid (about 120 s from the last confirmation) and stored. (2) the page's own code was served `no-store`, so each visit paid three serial trips (document, entry script, application chunk). The paint path itself does not wait on the network: with a record and a valid lease the rows paint 83 to 111 ms after the document arrives, before any frame. (3) The probe measured from the start of navigation, which includes the document's own trip, so no code could pass 300 ms at 1,500 ms. It now measures from the document's arrival and records the total beside it. Fixes: hashed bundles are `public, max-age=31536000, immutable` (Node host and Worker, `BUILT_ASSET_CACHE_CONTROL`); the probe waits until the first open's record is on disk before leaving. Fixing the paint exposed a loss: a message typed on the restored display was dropped when the early view was replaced by the real workbench. A restored state is now draft-only in the composer. The rule of when stored rows may show is `displayLeaseValid` (table of 9 rows). The lease rule is unchanged.

**Tests added.** S7 12 (`seams/S7`), S6 8 (`seams/S6`), the transport tier of the seams package (the 5 real-socket runtime files that drive the client, 55 tests, moved here), 6 memory and 8 IndexedDB device database cases, 4 restored replica tests, 9 display lease rows, 1 renderer test of the restored timeline and 1 of the restored composer, and the build of `page-lifecycle` over stub pages. The frozen record is `seams/S7/fixtures/device-record.v1.json`.

**Deleted (3).** `device-restore.transport` "shows the stored rows before any connection" and "does not restore into a replica that already read the session", and `AgentTimeline.replacement` "never shows an empty timeline between the replacement frame and its tail". Mutations (live-fold.ts): restore does not mark the display restored (the old test and 7 new ones fail: 4 client, 2 seams, plus the restored-composer test), restore ignores that the replica already read (the old test and 4 new ones), a replacement marker empties the held rows (the old test and 5 reducer tests and the S6 test). The spec expected about 20: the tests that reach the reducer through a fake server are, here, the three above; the rest (`journal-replacement.transport`, the other `device-restore` cases) assert wire behaviour (one `after` request, a reconnect, the item-key flag) and stay. Two real-server tests were rewritten: the image-recipient scoping test moved to the seams transport tier, and the same-key receipt test of `useImageDraft` now talks to scripted receivers (it was 1 slow real-socket test in the React package). One guard of `decideWindow` was removed: `held.state === 'complete'` in `sameItem` (mutation: no journal, Controller, Relay core or seam test fails without it). The other guard the M5 report called shadowed (a live-only mismatch in `planOf`) is not: removing it fails `journal-sync` "replaces a live-only copy with the window item of the same key", so it stays.

**Exceptions.** The 28 owned by M8 are lowered to 2: `layer` (3), `client-ui` (13, of which 8 were `window.` or `document.` read as globals: the rule now ignores property accesses and local `window` variables were renamed; 5 were real page reads, now behind `PageLifecycle`), and the cross-package paths of the client tests (6 and 6). The 2 left (`seams`, owner M10) are the Codex provider paths of `runtime-codex-images.transport.test.ts`.

**Scope.** A client-core change selected the `agent-remote-web` package (97 files, 1,008 tests, 14 s with jsdom per file) and its dependents lab, seams and debugger. It selects now `agent-client` alone for its own rule: 32 files, 437 tests, 13.6 s, almost all of it the real-socket `session-channel-transport` file, in the `node` environment with no jsdom; the replica, lease view, send state and device store files (131 tests) run in 0.45 s. Then the same dependents (client-web, lab, seams, debugger). The package-level graph does not select the runtime or the Controller: the runtime tests that drove the client moved to the seams package.

A change to a restored-state rule selects `replica/restored.test.ts` and `reducer.test.ts` (client), `AgentComposer.test.tsx` and `AgentTimeline.restored.test.tsx` (client-web), and the S6 and S7 suites: 20 seam tests in 1.15 s, and the unit files in under 2 s. Gate of this step: `pnpm test` 0 failures, `test:conformance` 31, `test:preview-browser` 73, `test:setup`, `arch:check`, `fixtures:check`, `compatibility:check` (protocol version unchanged). `pnpm smoke:quick` (seed 15900, build 43091124ce9e): M1, M2 and M7 pass; M1 first paint 99 ms (Claude) and 106 ms (Codex) at 300 ms and 2% loss. M1 at seed 100: 80 ms (50 ms, 2%), 103 ms (300 ms, 10%), 114 ms (1,500 ms, 2%), 114 ms (1,500 ms, 10%), all settled once. Left for later: the `session-channel-transport` and `message-echo-sync` files in `agent-client` are real-socket tests (16 over 300 ms, 5 over 1 s in the run); they belong in the transport tier (M12).

## M9 Client succession model (X1)

**Module.** `agent-client/src/succession` (module `client-succession`, layer 1): `locator` (session and role keys, canonical JSON), `history` (`sessionSuccessionHistory`), `refresh` (`reduceRefresh(state, event)` returning state and effects as data, `classifyFailure`, `staleRetryDelays`, `successionDeadlines`), `settlement` (`settlementOf`, `committedRefreshOf`, `handoffOutcome`, `restoredSourceOf`) and `evidence` (`resolveLocator`, `latestReplayByRole`, `continuesRole`, `canPruneSession`, `newerFavoritesHints`, `sourceStaleness`, `roleContextOf`). The contract is written in each file and in `seams.md` (S3, "Succession model"). `useSessionSuccession` keeps the requests, timers, bindings and documents; it builds each model input and applies the answer. `compositionRoleKey`, `canonicalJson` and the Workbench `sessionKey` are now the client's.

**Code moved.** About 150 lines of decisions, not the 700 the spec estimated: the rest of the hook's 1,152 lines is effects (attach, bindings, Ask recipients, display state) and composition-document edits, which stay in the Workbench because the document types are the Workbench's. The hook is 1,067 lines after (the moved code left, the glue that feeds the model came in). `App.tsx` did not change (3,755 lines): its succession lines are composition and view wiring; its `sourceStale` is a view rule that wraps the hook's.

**Tests added.** 140 unit tests under 20 ms in all (`history` 15, `refresh` 24, `settlement` 35, `evidence` 66; builders `buildSuccessionReplay`, `buildSuccessionChain`, `buildSuccessionCurrent`, `buildRoleEvidence` in `agent-client/testing`) and 10 S3 seam tests (`seams/S3/succession.integration.test.ts`, 30 ms, the real transport over an in-memory Relay).

**Mutation check.** 14 mutations of the refresh, settlement and evidence modules and 6 of history. Every mutation failed at least one model test (1 to 3). Old tests failed under: a notification ignored (`does not restore the confirmed locator after a refresh notification`), a missing route table without 404 (`keeps ordinary fixed navigation ... http_404`), a native session not required to settle (five hook-level tests, among them both cancelled and rejected variants of `waits for the original native session to recover`), a missing current role (`does not infer history from missing-current`), a title fallback (`builds unknown historical identities`). Many others were not caught by any old test (a timeout counted as unreachable, a replay-read flag ignored, many committed operations accepted, a restored source always settled, a wrong Handoff phase) so the model's tests add coverage and nothing was deleted for them. Four mutations of `sessionSuccessionHistory` (chain gap, origin, last replay, duplicates) are shadowed by other checks in both old and new tests.

**Deleted (5 tests).** The `notification` variant of `does not restore the confirmed locator after a refresh %s`; the `http_404` variant of `keeps ordinary fixed navigation available ... unsupported %s` (the `route_not_found` variant stays as the proof that the hook applies the effect); the `rejected` variant of `waits for the original native session to recover after a %s handoff` (the phase is `handoffOutcome`'s rows); `builds unknown historical identities` and the `missing-current` case of `does not infer history from %s role evidence` in `SessionSuccessionHistory.test.tsx`. The spec expected about 150. The five `App.succession.*` files hold 160 of their 163 tests now, and almost all of them assert what the Workbench does with the model's answers (windows, Ask, Team, Track, drafts, attach and recovery wiring), not a rule: a mutation of a rule fails them only through the shell, and the mutations that did fail them are the ones above. Deleting them needs the Workbench's composition state (X7, M13) to be a module, so the wiring can be tested without mounting `App`.

**Real-socket tests.** `session-channel-transport` (51) and `message-echo-sync` (2) moved from `agent-client/src/client` to `agent-remote-seams/tests/transport`, importing the package by name. `agent-client` unit: 437 tests, 11 over 300 ms and 2 over 1 s, 14 s, became 524 tests (with the 140 model tests and the unchanged rest), none over 300 ms, 1.3 s. The transport tier now holds 108 tests, 19 over 300 ms, 2 over 1 s; its target of 30 tests is M12's.

**The flake.** `retains an authorized desired B after its replay endpoint becomes unavailable` and `reconciles metadata on page resume without retrying an HTTP attachment failure` took 5.3 s and failed about 1 run in 3 with no load (both failed in one full lab run). The fixture's socket never answered the transport's resume probe (`ping`), so the page waited the probe's 4 s deadline (`foregroundProbeTimeoutMs`), then reopened the channel; only that reopen (`notifyFeedReopened`) made the page read the replays again, at 5.05 s, against the fixture `waitFor` deadline of 5 s. The tests now drop the Relay side of the socket (`dropSockets`, as a lost connection does) and the fixture sets the activity channel's first retry wait (`stateRetryMs`, a new transport option, default 1 s) to 20 ms. Both tests take about 320 ms and passed 12 of 12 runs. The extraction did not touch this; the cause was in the fixture and the transport's fixed waits.

**Scope.** A change to a succession rule selected `agent-client` (437 tests, 14 s) and its dependents: the Workbench (2,851 tests, 81 s with the two flaky failures), seams and debugger. It selects now the model (140 tests, 0.9 s), the S3 suite (76 tests, 1.9 s) and the hook file `useSessionSuccession.window.test.tsx` (15 tests, 2.8 s): 231 tests in about 6 s. The `App.succession.*` wiring files (160 tests, 18 s wall; 66 s summed over workers, the slowest file 16 s) are selected when the hook's shell changes. The Workbench wall time did not change: 81 s before, 84 s after, 0 failures.

**Exceptions.** None were owned by M9.
