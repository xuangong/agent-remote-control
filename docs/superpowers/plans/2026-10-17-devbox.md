# Full Product Devbox Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review these tasks.

**Goal:** Run the complete Agent Remote Control product, its matching Controller, and four native CLIs in one disposable-but-persistent Docker development and trial environment.

**Architecture:** Reuse the hosted Node Relay, built product UI, public pairing protocol, and packaged Controller. A Devbox-only composition supplies a fixed local identity without asking the user to authenticate. Production authentication remains unchanged.

**Tech Stack:** Node 22, TypeScript, existing hosted Relay, Docker Compose, native provider CLIs.

**Spec:** The user-approved requirements and boundaries below.

## Requirements

- One container, full product features, no standalone Lab or recorded provider as the product runtime.
- No website sign-in or manual Controller configuration/pairing.
- Real provider authentication remains native; an unconfigured provider must not prevent the website opening.
- Build the website and Controller from the same checkout. Install pinned native test baselines, with explicit version overrides.
- Use the Tencent npm registry for dependency installation.
- Persist Relay/Controller identity, native homes and history, session references, and workspace files across container recreation.
- Expose only the website on host loopback by default. Keep native services internal and use the existing Controller ownership model.
- Do not modify production authentication defaults, publish images/packages, deploy production, or use personal credentials in tests.
