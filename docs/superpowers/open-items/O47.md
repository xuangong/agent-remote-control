# O47: Our side holds a Codex thread longer than Codex needs

- Found in: M6
- Owner step: owner
- Status: closed

## Item

Our side holds a Codex thread longer than Codex needs, and a shown page stays live only while the Controller holds it: (1) the Controller keeps a session's runtime for its idle grace, 5 minutes after the last attach or turn, also when no page shows it, so a separate process is refused for about 6 minutes after a page's last use; (2) the terminal refresh (S6a D11) reads a Codex session through an attach, `thread/resume`, so Codex keeps the thread about 65 s after every refresh; (3) a journal-served page holds no demand, so 5 minutes after the open the Controller releases the session while the page still shows it: a shared-daemon terminal turn then reaches the page only through the refresh, 30 s after it ended, and the page says idle while it runs (02:53:58 open, 02:58:59 `session_idle_released`, 03:00:44 terminal turn, 03:01:14 shown)

## Status

closed (2026-11-21, step 3 of the provider boundary): the rule is visibility. The Relay tells a Controller that asks (`journalShown=1`) the complete set of its sessions that pages show (`journal_shown`, on registration and every change; a content stream of a journal-served page shows a session, an activity observer does not), and attaches a shown session the Controller does not hold. The Controller keeps a shown session resident (`session-core/residency.ts`, a pure rule with a vector table, used by `idle-sessions.ts`), and lets one no page shows go after a grace keyed on the declared behaviour, never the provider id: 10 s for a CLI that keeps a session loaded after its last client (Codex, which then unloads it 70 s later, so within 80 s of the last page closing), 15 s for a subscription, 60 s for a shared process, 5 minutes for a process of its own or an undeclared adapter. Root causes: (1) and (3) a fixed 5-minute grace and no demand from a journal-served page. Was: needs a Controller release and an S2 signal. Proposed: the Relay tells the Controller which sessions a page shows, the Controller holds those and releases the others after a grace close to Codex's own unload, and the refresh reads Codex history with read-only methods (`thread/turns/list`) instead of an attach. Reproduced in the CLI simulator (step B2) and turned green: `agent-remote-seams/tests/S2/session-residency.integration.test.ts`. Not changed: the terminal refresh still reads an unshown Codex session through an attach, so Codex keeps it about 65 s after each refresh; a read-only refresh waits for a native check that `thread/turns/list` reads an unloaded thread without loading it (`reread.withoutAttach` is declared false). Every Controller must update; the Relay deploys first
