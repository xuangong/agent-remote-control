# O69: Tasks on the Team path lack the rest of the task model

- Found in: step T2a of the [assistant tasks design](../specs/2026-11-23-assistant-coordinator-and-tasks-design.md) (2026-11-23)
- Owner step: T2 and T3 of that design, after the P2 operation queue (T0)
- Status: open

## Item

T2a runs create, brief, report and result end to end on the Team delivery path. These parts of the design are not built yet:

- **Delivery rules of 5.4.** Several results for one main session are delivered one per idle moment instead of coalesced into one
  input, and nothing orders a session's waiting input across kinds (the person's held messages, needs-input events, results,
  assistant messages). Echoes carry no requester.
- **Task states.** `needs_input` (a worker's pending interaction or `ask_owner`), `cancel_task`, `message_task`, `mark_task_done`
  and stall events do not exist. A worker whose creation outcome is unknown leaves its task `queued` with the error; design 6.7
  moves it to `needs_input` with `brief_unknown`.
- **Workbench.** Task cards render from the framed input only: they do not open the worker session, and the assistant's details
  have no task list. Bot mode has no side panel for a task thread.
- **Placement.** Workers run on the owner's Host and provider in the owner's directory (`workspace: same`); `read_only`,
  `worktree` and `remote` workspaces, and choosing a provider or model, are not offered.

Fix: build them as T2 and T3 describe once the P2 queue carries `task_brief`, `task_event` and `task_input`.
