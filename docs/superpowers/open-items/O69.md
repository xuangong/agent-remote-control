# O69: Tasks on the Team path lack the rest of the task model

- Found in: step T2a of the [assistant tasks design](../specs/2026-11-23-assistant-coordinator-and-tasks-design.md) (2026-11-23)
- Owner step: T2 and T3 of that design, after the P2 operation queue (T0)
- Status: open

## Item

Tasks run end to end on the Team delivery path: create, brief, report and result; coalesced updates; questions (`ask_owner`),
pending interactions, one reminder then `no_report`; `message_task`, `cancel_task` and `mark_task_done` from the owner and the
page; what the person types to a worker reaching its owner; uncertain deliveries and creations waiting as `brief_unknown`;
`read_only` and `worktree` workspaces with the patch; another provider or model. These parts of the design remain:

- **Delivery rules of 5.4.** Nothing orders a session's waiting input across kinds (the person's held messages, task updates,
  assistant messages); task updates only wait for idle and coalesce among themselves. Echoes carry no requester.
- **Stalls (8.5)** and the per-Host and per-turn limits of 8.3. Only the running tasks per main session are bounded.
- **Placement.** `remote` workspaces and tasks on another Host; `continue_task`; result resources other than the worktree patch,
  which is a file on the owner's Host.
- **Workbench.** The task thread opens as an ordinary session view: it has no Mark done or Stop in its header and no Interrupt or
  Queue choice in its composer (both are in the assistant's details). Bot mode has no side panel for a task thread. Task rows have
  no unread dots, and needs-you tasks do not drive the assistant's needs-you dot or reminders.

Fix: build them as T2 and T3 describe once the P2 queue carries `task_brief`, `task_event` and `task_input`.
