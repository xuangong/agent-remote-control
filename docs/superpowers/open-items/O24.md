# O24: With smart reading off for a provider, a Controller restart moved a reader to the first row

- Found in: M14
- Owner step: M15
- Status: closed

## Item

With smart reading off for a provider (the legacy read path), a Controller restart moved a reader in the middle of a conversation to the first row

## Status

closed: not a regression, the same at the baseline tag (real Claude session, restart of the instance: the marked row moved from 194 px to 982 px, scrolled to the first row). The key of a row without item keys carried the journal epoch, so a replacement epoch gave every row a new key, `absorbWindow` kept none, and `useTimelineScroll` found no row with the saved key. The epoch is no longer part of the key (`timelineEntryKey(entry)`); a row keeps its key and its object when the replacement brings the same row, and is replaced by content when it differs. Pinned by `timeline-entry-key.test.ts` (unit), the reducer test of unkeyed replacement, and an E3 flow with smart reading off; on the HEAD instance the marked row stayed at 194 px through a restart
