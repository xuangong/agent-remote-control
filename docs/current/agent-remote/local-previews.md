# Local previews and file resources

The hosted Controller can expose a workstation's loopback HTTP service through an authenticated preview origin. Markdown local images and file links use the session resource protocol independently of port registration. Both features require the updated browser, Relay, and Controller.

## Preview flow

A timeline block containing a loopback URL offers **Open preview**. Rendering a block does not register its port. Registration records the source session and timeline item on the Controller. Root-mounted apps open immediately after registration; configured-base apps show their registration ID for configuration first. **Open preview** in either the timeline or Host preview list prepares and redeems a short-lived entry proof, then opens an iframe browser inside the current workbench. No new tab or top-level navigation is required, including Safari Home Screen standalone mode.

**Copy tunnel URL** beside **Open preview** in the timeline and Host list prepares a fresh entry link without opening an iframe, registering the target first when needed. It preserves the selected target path, query, and fragment. Copy feedback appears beside the action; if clipboard access is denied, a selectable URL is shown. The copied URL is a navigation link containing only the Host, preview ID, and destination path, never a credential. A browser without an Agent Remote login goes through the existing Gateway sign-in flow and returns to the selected preview. The current account must own the Host; sharing the URL does not share access. The registration must still be active.

The public route is `https://agents.xianliao.de5.net/p/<id>/<path>?<query>`. Registration selects one fixed loopback origin, including its port. HTTP paths and WebSocket handshakes cannot choose another target. No public wildcard hostname or wildcard certificate is required.

The Controller opens a separate outbound WebSocket to `/ws/preview-tunnel` on the control origin. HTTP request and response bodies use multiplexed binary chunks with credit and cancellation; SSE passes through as a stream without collecting the full response. WebSockets have an independent upstream handshake, selected subprotocol, text/binary messages, and close propagation. The data connection reconnects independently of chat. Interrupted requests fail and are not replayed.

The Controller persists registrations under its state directory, scoped to Relay origin and Host identity. The registration lease defaults to one hour. Authenticated HTTP requests, forwarded upload/download chunks, SSE data, and application WebSocket messages renew this lease independently of any workbench iframe. Merely keeping a socket connected, transport heartbeats, list polling, and rejected unauthenticated requests do not count as activity. Relay coalesces traffic per Host and registration: at most one renewal is in flight, writes are normally spaced by up to one minute (or one third of the remaining lease for short leases), and a trailing renewal preserves the last observed activity. Once traffic stops, no recurring traffic keepalive remains. Restart preserves the stored deadline; it does not extend it. An authenticated owner renewal extends the deadline by the configured lifetime while retaining the registration ID, target, path mode, and sources. Expired records can be renewed if still present in bounded history, the target probe succeeds, and active capacity permits; unregistered records cannot be renewed. Expired and unregistered records remain as bounded history. Active registrations reconnect after the control connection registers again. With no active registrations, the data connection closes.

Full snapshots carry an epoch and revision over the control uplink. The browser refreshes the Host preview list every five seconds and when the tab becomes visible. The HTTP list response includes only active registrations; full Controller snapshots and Relay persistence retain bounded lifecycle history for renewal and removal reconciliation. Connectivity and lifecycle are separate: an active registration can be offline. Both desktop and compact Host preview lists show only active registrations, with source links and unregister controls. Opening a preview from the compact Host list closes the supporting drawer so the preview and conversation can receive input. An offline unregister is durably queued at Relay, immediately blocks routing there, and is retried after Controller reconnect until an authoritative snapshot confirms removal.

## Authorization

Only the Host owner can register targets, prepare preview access, list registrations, or unregister. Existing Host sharing does not grant preview or arbitrary local image resolution rights.

After current-browser login and Host ownership verification, the internal entry URL contains a one-use proof in its fragment, valid for 60 seconds. This internal handoff is not the URL exposed by Copy tunnel URL. Redemption also requires the receiving browser to be logged in as the same user. The workbench redeems the proof through a same-origin POST before mounting the iframe, obtaining an HttpOnly, host-only browser-session cookie scoped to `/p/<id>/`. The Relay enforces a one-hour sliding inactivity deadline for that authorization, extended by authenticated preview traffic as well as explicit renewal. This keeps an active SSE or WebSocket stream usable beyond the original hour without requiring response headers to update a browser cookie. Expired authorization cannot be revived by late traffic; original Relay login and ownership checks still apply. The iframe receives only the final preview URL. Direct entry-page consumers can still redeem the fragment through the existing handoff page; that page itself disallows framing. No Relay login cookie or tunnel credential is forwarded to the local service. Authorization and proxy identity headers are stripped; the upstream Origin is rewritten to the registered local origin after validating the browser origin at Relay. Each HTTP request and WebSocket handshake checks both the receiving Relay browser session and the current request login, current owner access, active registration, and Controller availability. Logging out invalidates preview access and existing streams. Browser previews use the same origin as the control site so its host-only login cookie is available; a separate preview hostname cannot redeem handoffs without its own authenticated browser binding and fails closed. Raw transport clients must explicitly supply both credentials. Existing streams are rechecked on lifecycle changes and at most every 15 seconds, subject to the existing Gateway authority lease.

Previews use the control origin by default. The Relay reserves `/p/<id>/` and `/_arc/enter` for previews while preserving the main UI, authentication, session APIs, and control WebSocket routes. Preview scripts share the control site browser privileges: they can call authenticated main-site APIs and access its storage. Cookie paths and upstream credential stripping do not isolate same-origin scripts. Use this mode only for trusted local applications. A separate preview origin remains configurable to isolate preview scripts from the control site; previews on that origin still share browser privileges with each other. Service worker registration through preview routes is denied. Unknown request hostnames are rejected.

Targets are loopback HTTP or HTTPS origins. The Controller validates target addresses, redirects, methods, paths, headers, frame sizes, stream limits and queue bounds. Redirects are returned to the browser rather than followed by the Controller. Configure protected local ports if other administrative services listen on TCP.

## Embedded browser

On desktop, Conversation and the preview browser share the workspace equally, with Conversation on the left and the iframe on the right. Both panes remain interactive. Dragging the divider adjusts their widths while preserving a 280 px minimum for each pane when space allows; arrow keys also adjust it, and double-click or Enter restores the equal split. Minimizing restores the conversation to full width, and reopening retains the adjusted split. On mobile, the browser fills the viewport as a modal dialog with safe-area padding. Switching between layouts retains the iframe document. The underlying conversation stays mounted, preserving its scroll position and draft. **Minimize preview** shrinks the browser toward a compact dock on the source session’s right edge, without allocating another toolbar row. The iframe stays mounted while minimized, preserving application state, scroll position, and its navigation history. Clicking the dock restores the same browser without requesting another entry proof. Previews are scoped to their source session, so switching sessions on the same Host keeps each session’s previews available. The dock remains available when the mobile conversation heading is hidden. The 240 ms transform and opacity animation honors reduced-motion preferences. Closing from the toolbar or dock removes that iframe and aborts its pending entry request without unregistering the port. Changing Hosts or leaving the page releases the retained browsers. Confirmed unregistered or unavailable registrations remove the iframe. An ID absent from the active list can still be renewed and does not by itself remove an owner’s retained iframe. Expiry and Controller disconnections display a recovery notice while retaining the iframe document. Entry requests and initial page loading have a 20-second deadline or loading notice.

In addition to traffic-driven renewal, a retained iframe renews its registration and preview authorization, including while minimized or attached to another session on the same Host. Renewals are deduplicated by registration within each provider and run after one third of the remaining lease, at most five minutes apart. Each request has a 20-second deadline; transient failures retry after five seconds. Retained previews can renew by ID even when omitted from the active list. An HTTP 409 renewal rejection confirms that the registration is unavailable or unregistered and stops further attempts, including wake-triggered retries. Returning to a visible page, restoring a page from the browser cache, and coming online trigger an immediate attempt. Closing the last retained browser for a registration, changing Hosts, leaving the page, or receiving manual unregister stops renewal. Independent preview windows continue renewing through their own traffic after the workbench closes. When both iframe keepalives and traffic stop, the Controller expires the lease normally.

Registration renewal uses the authenticated Host owner endpoint. `POST /p/<id>/_arc/renew` is reserved for preview-cookie renewal and never reaches the local application. It revalidates the original Relay browser session, ownership, and active registration before extending the existing HttpOnly cookie and the authorization object held by active HTTP/WebSocket streams. If suspension outlasts the cookie, the client obtains a new one-use entry proof and redeems it without navigating the retained iframe. A suspended operating-system process cannot send keepalives: expiry can interrupt streams during suspension, and recovery does not replay lost requests. The local application remains responsible for reconnecting its own interrupted sockets.

Back and Forward use a panel-owned URL history instead of traversing the parent conversation history. The address bar displays the local target followed by an arrow and the mapped preview URL. Full-document navigation, hash changes, and History API changes update the mapped address. Toolbar history navigation reloads the selected URL; it does not restore arbitrary application JavaScript state or replay POST bodies. Same-origin links and forms targeting another window are kept inside the iframe, and subsequent `window.open` calls use the frame. The sandbox does not grant popups or top navigation, but trusted same-origin application scripts are not a security isolation boundary. Cross-origin pages cannot expose their navigation to the toolbar and may refuse embedding; the panel retains Reload and Close controls. Applications that disallow framing need their own frame policy configured.

The embedded workbench requires previews on the Relay origin. An explicitly configured separate preview origin still supports direct entry links through the headless client, but cannot use this same-origin redemption and navigation UI. Browser acceptance runs on Chromium and WebKit with desktop and mobile viewports, including adjustable split panes, simultaneous conversation and iframe input, responsive mode changes, minimize/restore document identity, application form and scroll preservation, session-specific docks, close cleanup, and reduced motion; installing WebKit with `pnpm --filter @agent-remote-controller/agent-remote-lab exec playwright install webkit` is required for `pnpm test:preview-browser`. These tests do not substitute for a physical iOS Home Screen installation check.

## Application paths

| Mode | Upstream path | Supported behavior |
| --- | --- | --- |
| Root-mounted app (`strip`) | `/p/<id>/me` becomes `/me` | Same-target redirects, app cookie paths, and supported HTML/CSS references are rewritten under the preview prefix. |
| Configured preview base (`preserve`) | `/p/<id>/me` stays `/p/<id>/me` | The app generates its own prefixed links and WebSocket URLs. HTML/CSS bytes pass through. |

HTML/CSS adaptation is bounded to 1 MiB of decoded UTF-8 content and accepts identity or gzip encoding. Partial 206/Content-Range responses pass through unchanged. It parses static attributes and styles rather than rewriting JavaScript source. Relative references keep browser-relative semantics; supported root-relative and same-target references receive the prefix. Arbitrary JavaScript-generated URLs, service workers, cross-port APIs, and every framework's root assumptions cannot be transparently adapted. Use a configured base for development servers and complex apps.

For Vite, register using **Configured preview base**, copy the returned ID, and set the base and browser-facing HMR endpoint before restarting the local server:

```ts
export default {
  base: '/p/<id>/',
  server: {
    host: '127.0.0.1',
    hmr: {
      protocol: 'wss',
      host: 'agents.xianliao.de5.net',
      clientPort: 443,
    },
  },
};
```

A new registration can have a new ID, requiring a corresponding base update. Multiple apps are selected by their explicit route prefix; the router does not infer an active app from Referer.

## Configuration

No additional domain configuration is needed for same-origin previews. With `AGENT_REMOTE_PREVIEW_URL` unset or empty, previews use `AGENT_REMOTE_RELAY_URL`, including the existing DNS and certificate. Node Docker and Workers share this default. The Workers configuration declares only the control Custom Domain. An optional `AGENT_REMOTE_PREVIEW_URL` can select a separate origin after its DNS, certificate, and routing are configured. Reverse-proxy preview paths to the Relay listener, preserve Host and Origin headers, support WebSocket upgrades, and turn off response buffering for SSE. Configuration in source does not deploy the service.

The Controller CLI enables previews with its existing managed state directory. `AGENT_HOST_PREVIEW_TTL_MS` sets the registration lease lifetime in milliseconds; the default is `3600000`. `AGENT_HOST_PREVIEW_PROTECTED_PORTS` accepts comma-separated TCP ports. Programmatic `createAgentHost` users enable the feature through the optional `preview` configuration.

A single application WebSocket message is limited to 256 KiB minus a 512-byte framing allowance. Larger payloads require application-level chunking.

Workers exposes no WebSocket drain metric. Application-facing preview WebSockets therefore have a conservative 16 MiB lifetime egress budget and close with code 1013 when reached; clients can reconnect. Dedicated Controller tunnel traffic instead uses explicit peer credit to bound outstanding data. HTTP/SSE is not subject to that application-WebSocket lifetime limit.

## Markdown local resources

`react-markdown` and a rehype node marker identify actual inline and reference images and file links. Code fences and ordinary text do not trigger file reads. Local locators include `/absolute/path/image.png`, `file:///absolute/path/image.png`, and relative paths such as `./assets/image.png`. The parser does not turn these into requests to `agents.xianliao.de5.net/Users/...`.

The browser resolves an unbound locator through `resource_resolve_request`, authorized separately as `resolve_resource`, then reads the returned session-scoped resource ID through `resource_request`. Existing bindings remain readable through their existing authorization. The Host captures the session's initial `runtimeInfo.cwd` as the authorized root. Relative references use the source document directory when an absolute source locator is available, otherwise the session root. A session with no valid cwd cannot resolve local file paths.

Canonical paths must remain under the authorized root after symlink resolution. Reads require a regular non-empty file, are limited to 4 MiB so Base64 responses fit the existing control-frame limit, and inspect file bytes. PNG/JPEG/GIF/WebP render as images. UTF-8 source files, Markdown, JSON, HTML and SVG are limited to 1 MiB; binary data, arbitrary URI reads, directories, empty files, missing files and out-of-root paths return unavailable. HTML and SVG are previewed only as source text, never as active documents. The renderer shares bounded resolve/request caches and renders available bytes as an inert image data URL. Image component identity and resolved bindings survive unrelated replica updates and streamed text additions, preserving the decoded image DOM without another byte request. Session, source document, or locator changes invalidate the displayed binding; resource unavailability and replica payload resets still update the image state. It does not register a port or expose a filesystem HTTP mount.

The resource ingestor extracts optional `imageDimensions: { width, height }` from PNG, JPEG, GIF, and WebP headers, applying JPEG EXIF rotation. Dimensions are tied to the stored content digest and included in available resource metadata and byte responses. `resource_resolve_response` includes metadata without Base64 content, so the client can reserve space before the separate byte response arrives. Metadata updates for the same digest retain downloaded bytes. Malformed or unsupported headers omit dimensions without blocking the existing resource flow.

Markdown images use the same frame for loading, display, and failure. Known dimensions establish its aspect ratio, capped by the container width, intrinsic width, and 70vh height. Loading uses a low-contrast pulse; successful browser loading reveals the image with a short opacity transition. Transport, resource, and decoding failures stop the loading animation and retain the known frame dimensions with an unavailable label. Reduced-motion preferences disable both animations. Changing the session, source document, or locator resets retained dimensions. Before dimensions are known, the renderer shows a compact loading label; metadata arrival can still cause one initial layout adjustment. Remote HTTP(S) Markdown images remain inert alternative text.

## File sidebar

Local Markdown links open a file sidebar without navigating the workbench or creating a browser request to the raw path. Absolute paths, relative paths and `file://` locators use the same authenticated resolve/read messages as inline images. Clicking an inline local image opens the same sidebar. HTTP(S), mail and document-anchor links retain their existing behavior. Line suffixes such as `#L12` and `:12:4` select the source line.

CodeMirror loads only when a text preview opens. It displays syntax-highlighted, read-only source, including Markdown, with line numbers, selectable text, search keyboard shortcuts and a line-wrap toggle. Both the state and the DOM disable editing, so opening source on a phone does not activate the soft keyboard. Images retain the dimensions-aware loading frame. The panel header shows the file name and original locator, refresh and close controls; the footer shows read-only status and byte size.

The desktop sidebar starts at half of the conversation area and shares its keyboard/pointer-adjustable divider. Both sides remain interactive. At widths up to 760 px the sidebar is a full-screen modal. Opening a file minimizes the active webpage preview; reopening a webpage closes the file sidebar. A session, Host or timeline epoch change closes the file sidebar and discards its display state. Closing restores focus to the original trigger if it still exists.

Resource resolution and byte requests share bounded caches with inline images. Refresh resolves again and reads the current file contents; it does not modify the immutable resource snapshot already used by the timeline image. Failed resolutions are not cached permanently. Requests show a failure after 20 seconds, offer retry, and ignore late results after timeout, close or file change. Resources stay restricted to the session workspace, including after symlink resolution; this is not arbitrary Host filesystem access.

## Validation

Focused tests cover real outbound Controller HTTP binary data and uploads, early SSE delivery, WebSocket subprotocol and binary messages, owner isolation, unregister cancellation, persistent registrations, and protocol queue limits. A real session WebSocket test resolves a document-relative PNG and reads exact bytes through the existing resource protocol. Renderer tests cover inline/reference images, source context, deduplication and code-fence non-resolution. Miniflare/workerd tests exercise real local HTTP/WebSocket forwarding and persist snapshots and offline removal across Durable Object restarts. `pnpm test:preview-browser` launches Chromium against a real Node Relay and Controller: it verifies a prefixed Vite app with hot reload and a local Markdown PNG loaded through actual authenticated resource frames. Chromium and WebKit layout tests hold real image response frames to verify dimensions arrive first, then compare image bounds and following text positions across successful loading and decoding failure at phone and desktop widths. They also check reduced-motion styling. File sidebar browser tests exercise real authenticated Relay/Host resource messages for source, Markdown, inert HTML, image display, refresh, missing-file recovery, denied paths, resizing and session changes in Chromium and WebKit at desktop and phone widths. Component tests cover timeout and stale-response rejection. The browser fixtures do not start a native provider CLI.

The Lab regression run excludes the opt-in native Codex process suite and retains its existing skipped cases. No production Controller, external native daemon, public domain, or deployed Relay is used by this acceptance.
